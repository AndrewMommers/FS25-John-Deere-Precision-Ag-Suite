Building a true AutoPath system is the holy grail of precision ag modding in Farming Simulator. It completely changes the standard "A-B line" GPS mods currently available (like VCA or Guidance Steering) by making the guidance dynamic.

Here is exactly what John Deere’s AutoPath does in the real world: It records the exact location of crop rows during the very first pass (usually planting). For every subsequent pass—whether you are side-dressing, spraying, or harvesting—the system automatically generates new guidance lines based on those original planted rows, perfectly accommodating different implement widths and curved boundaries without you ever having to set a new track.

To build this as a "full-on mod" integrated with your G5 display app, you need to build three distinct engines.

1. The "First Pass" Data Logger (Lua)
AutoPath is useless without the original planting data. Your Lua script needs to hook into the game's SowingMachine specialization.

The Hook: When the seeder is lowered and active, the script must start logging an array of X and Z world coordinates (FS25 uses X for East/West and Z for North/South) at regular intervals (e.g., every 1 meter of travel).

The Data: You aren't just logging a single center line. You must log the tractor's exact path, the heading, and the working width of the planter.

Storage: This data must be written out to a JSON or XML file specific to that field (e.g., Field_14_Planted_Rows.json).

2. The AutoPath Math Engine
This is the core of the mod. When you come back to the field months later with a sprayer, the system must calculate a new path. If you planted with a 12-meter planter and are now spraying with a 36-meter sprayer, the sprayer should cover exactly three planter passes at once.


Key insight: The math gets extremely complex on curves. You cannot just draw a parallel line. You must use mathematical algorithms (like offsetting a polyline) to ensure the inner radius of a curved path doesn't pinch or overlap.

3. The AutoTrac Steering Controller
Once your Math Engine generates the new target coordinates, you have to make the tractor actually drive them.

Instead of letting the player steer, your Lua script must hijack the Steerable vehicle class in FS25.

You will need to implement a PID (Proportional-Integral-Derivative) controller in Lua.

The PID calculates the "Cross-Track Error" (how far the tractor is from the blue AutoPath line) and the "Heading Error" (is the tractor pointing parallel to the line?). It then applies a steering angle directly to the wheels to smoothly bring the vehicle onto the path and keep it there, exactly like a real StarFire receiver guiding a steering column.

4. Tying it to the G5 App
When you load into a field, your web app pulls the Field_14_Planted_Rows.json file.

The planted rows render as yellow lines on your Leaflet map.

When you unfold your sprayer, the web app calculates the track spacing, generates the new blue guidance lines, and sends those target coordinates back through your WebSocket to the Lua steering controller in the game.

You can then build in the "Shift Track" feature on your UI, allowing the user to tap arrows to nudge the guidance line by a few inches, adjusting the coordinates in real-time.

The Logic: The player drives the combine. The Lua script in the combine reads its own speed, heading, and the position of its unloading pipe. Can we use the default FS25 ISO Compact?

Yes, we absolutely can. Pivoting to use FS25’s native in-cab dashboard rendering (often referred to as the ISOBUS Virtual Terminal or ISO Compact system) completely changes the architecture of the project.

Instead of building a separate web app running on a second monitor or tablet, you bring the entire John Deere G5 experience inside the tractor cab, rendered directly onto the 3D monitor model in the game.

This is how most high-end tractor mods operate (often utilizing scripts like Dashboard Live), but it comes with a strict set of trade-offs regarding what the Giants Engine can and cannot render.

Here is how the project shifts if we use the native FS25 ISO Compact approach:

What Changes in the Architecture?
No WebSockets or Node.js: You can scrap the external server entirely. Everything runs 100% locally within the FS25 Lua engine and vehicle XML.

Plug-and-Play: The mod becomes a standard .zip file that anyone can drop into their mods folder without needing to open ports or run background applications.

Immersion: The G5 terminal sits right in the cab. You can use Interactive Control (IC) mods so the player actually reaches out and clicks the screen in first-person view to activate AutoPath or Machine Sync.

The Trade-Offs (The Giants Engine Sandbox)
Building a UI inside the FS25 engine is drastically different from using modern web tools like React or Leaflet.

Mapping	Fluid, high-res satellite maps with complex overlapping polygons.	Highly Limited. You are restricted to displaying the game's base PDA minimap.
Path Visualization	Easy. Drawing dynamic curved lines for AutoPath is standard math.	Difficult. The FS25 2D drawing API (renderOverlay) is primitive. Drawing dynamic curved vector lines onto an in-cab screen is notoriously performance-heavy.

## 📐 Mathematical Foundations

### AutoPath™ Polyline Offsetting
The cross-track error $e_{ct}$ between the tractor's instantaneous position $(x_{veh}, z_{veh})$ and the nearest recorded planting reference point $(x_{ref}, z_{ref})$ with heading $	heta_{ref}$ is calculated as:

$$e_{ct} = (x_{veh} - x_{ref})\sin(\theta_{ref}) - (z_{veh} - z_{ref})\cos(\theta_{ref})$$

### Closed-Loop PID Steering Controller
The target steering wheel angle $\delta(t)$ required to eliminate cross-track error is dynamically calculated in Lua using:

$$\delta(t) = K_p e_{ct}(t) + K_i \int_{0}^{t} e_{ct}(\tau)d\tau + K_d \frac{de_{ct}(t)}{dt}$$

Where:
* $K_p$ = Proportional gain (immediate error magnitude response)
* $K_i$ = Integral gain (eliminates steady-state offset on sidehills)
* $K_d$ = Derivative gain (dampens oscillation along straight passes)
